> ## ⚠️ Read this before upgrading
>
> **This release can turn a passing run into a failing one, and it is meant to.**
>
> Six classes of step used to be reported as `PASSED` while nothing was
> actually verified. They are now reported as `WARNING` (exit code **3**),
> `UNVERIFIED`, `SKIPPED` — or, in one case, `FAILED` (exit code **1**). If your
> pipeline treats any non-zero exit as a failure, a suite that was green on
> 1.7.1 may stop being green on 1.8.0 — **the run did not get worse, the report
> got honest.** Read the warning lines before changing anything in your app.

---

## What changed in the verdict

| Before (1.7.1) | Now (1.8.0) |
| --- | --- |
| Text went into a different field than the step named → `PASSED` | `WARNING`, naming both fields |
| Target was a `<select>`, `readonly`, `disabled`, or still empty after typing → `PASSED` | `WARNING` |
| Steps that ran after a failed step → `PASSED` | `UNVERIFIED` (only in runs that already failed) |
| A scenario-level `expected_result` written as an ordinary sentence → silently passed | `WARNING` — nothing was checked there |
| `if_visible: true` on an element inside a collapsed container (`height: 0; overflow: hidden`) → step ran | step is `SKIPPED` |
| `text_visible` / `assert_text` on text inside a collapsed container → `PASSED` | **`FAILED`** (exit code **1**) |

The first four raise the exit code from 0 to 3 on runs that have no real
failure. The fifth does not change the exit code, but a later step that
depended on that click can now fail.

**The sixth is the one to read twice.** It is the only change here that turns
a run red rather than amber, because the assertion is being answered correctly
for the first time: the words were in the DOM and no reader could see them.
If such a step now fails, either the page stopped showing something it used to
show, or the assertion was never true. Both are worth knowing; neither is new
breakage in your app. Text that is merely below the fold, or inside an inline
element carrying `overflow: hidden`, still passes — those were measured
specifically so this change could not be mistaken for "assert less".

## Fixes that turn red into green

- **`assert_screen_changed` could never pass.** It compared a step's own start
  against its own end, with no action in between — `0.0%` was the only answer
  it could give. `aat devqa --verbosity detailed` auto-injects one of these
  after every click, so every detailed AI-generated scenario carried one
  un-passable step per click. Fixed.
- **Self-healing never fired.** When a selector broke, AWT was supposed to find
  the element from a screenshot it had banked on an earlier run. Five separate
  links in that chain were broken; the feature had never run in the field.
  Fixed and measured against a real Chromium with the selector renamed
  underneath it.
- **Flutter CanvasKit apps.** AWT now waits for late-arriving web fonts and for
  the Flutter bootstrap to finish before it photographs or reads the page —
  evidence screenshots used to come out as rows of tofu. The OCR fallback also
  now uses the languages you configured in `matching.ocr_languages`; it was
  reading everything as English. A scenario with every hand-tuned `wait:` step
  removed now passes end to end.
- **Elements below the fold.** When the DOM could not name an element, AWT only
  ever looked at the first screenful. It now scrolls and re-looks, in the
  matcher chain, in self-healing, and in the `text_visible` OCR fallback.
- **Collapsed containers read as visible.** `if_visible` treated an element
  inside a `height: 0; overflow: hidden` parent as visible — that is how
  accordions and dropdowns are usually built. (The same question asked by
  `text_visible` is in the table above, because there it turns runs red.)

## New

- `aat learned list` — what AWT has learned, including banked screenshots.
- `aat learned clear --templates [--host <host>]` — clear the screenshot bank,
  all of it or one host.
- `aat doctor` now reports missing Tesseract language packs. A missing pack
  used to surface as `Text '…' not visible on page` — the diagnosis blamed
  the page.
- `.aat/runs/<timestamp>-<n>_<scenario>.json` — run history, 50 deep.
  `.aat/last_run.json` is unchanged in name and shape.
- `aat loop` ends with a plain-language verdict: what broke, what AWT did
  about it, and how to undo it.
- Warning summaries now say what kind of warning occurred. They used to print
  the same two sentences regardless, which meant they were wrong most of the
  time.

## Safety

- The AI fix loop now refuses a change that deletes assertions or error
  handling, and it checks the file on disk rather than the model's claim about
  what the file contained.
- Choosing `--approval-mode auto` prints what it is about to do to your files
  before it starts. The default is still `manual`, which writes nothing.
- The paid-upgrade line that appeared only to users whose third attempt had
  failed is gone, with no replacement.

## Requires your attention

If a run that used to be green now exits 3, read the `WARNING` lines first.
The most common cause is the first row of the table above: the step named one
field and the text landed in another, usually because the page's placeholder
text matched before its label did. AWT now resolves exact labels first, so many
of these will simply be correct; the ones that remain are real.

If a run now exits 1 on a text assertion that used to pass, open the page and
look for the words. If they are inside a collapsed accordion, tab, or
dropdown, the assertion was passing on text nobody could read.
